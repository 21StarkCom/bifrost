# Warnings and errors: what to do

## Warnings

Actions return `"warnings": [...]`, usually empty. With each, the action happened: do not repeat it.
For `text_unchanged`, the insert was sent but the field did not change: observe before you repeat it.
For `effect_unverified`, the press was sent and nothing read what it did: observe before you repeat it.

| Warning | Meaning |
|---|---|
| `app_self_activated` | An app activated itself during the action, and the app that was in front was put back. |
| `observe_failed` | Its `--observe` failed: run `observe` yourself. A later batch step that references it fails `stale_snapshot`. |
| `space_restore_failed` | The focus fallback switched to the window's Space for the verb, and the Space that showed before did not show again after the switch back (see the focus fallback in [focus.md](focus.md)). The user's screen may still show the other desktop: tell the user. |
| `hide_restore_failed` | The focus fallback unhid the window's app for the verb, and the app did not hide again. Its windows may still show: `hide` the app. |
| `minimize_restore_failed` | The focus fallback restored a minimized window for the verb, and it did not minimize again. The window may still show: minimize it with `window-state`. |
| `restore_failed` | A foreground verb, or a focus fallback that activated an app, acted, but the app frontmost before had quit or did not come back to the front within 1 s, so there is no `restored`. The target's app may still be in front and no verb brings the user's app back: tell the user. The hold's reads and the 5 s watch after it can still put the user's app back a moment later, so read `apps`' `active` again first. |
| `record_failed` | Its line could not be written, so replaying the recording skips that step. An action on a `find` target always gets it, as its match has no tree path to replay; so does one on a menu snapshot's target, the menu gone by replay; and so does one on a pixel or text target on a window the PNG showed over its window, a sheet or a popover gone by replay. |
| `hover_interrupted` | Someone moved the mouse pointer off `hover`'s point during its hold, or held a button at its end, so it was left where it was: what ran inside the hold may have run without the hover, and its `observe` may not show what the hover reveals. Observe before another hover. |
| `frame_adjusted` | `window-frame` put the window at the position asked for, but its app holds it at another size (its size steps, a minimum or a maximum), so `frame` has that size, not the one asked for: work with the size in `frame`. A replayed `window-frame` adds it to replay's `warnings` the same way. |
| `text_unchanged` | `type` inserted its text into an element target and the app accepted it, but 1 s later (and again 250 ms after) the field's character count and selection read as before the insert. Also: `type` sent LibreOffice its text as key events, and both times the element's count and selection, the app's focused element and how often the text shows in the window's tree read as before (see `type`, LibreOffice, in [actions.md](actions.md)). The text may not have landed: observe the field before you type again. |
| `effect_unverified` | A single left click into web content outside the Chromium family (a `click`, or a `hover --click` press's fallback) went as the press of the element at its point, which the app accepted, and nothing reads its effect back (see the single click in [targets.md](targets.md)). Also a click into LibreOffice that went as the press or the focus of the element at its point, or as an element target's focus (see `click`, LibreOffice, in [actions.md](actions.md)). Observe the window to see what the click did. |

## Errors: what to do

| Code | Do this |
|---|---|
| `permission_missing` | A grant is missing, which the message names (`observe --detect` needs Screen Recording, as `--screenshot` and `--ocr` do, and so does an action on a text target; `ocr` and `find-text` need none; so does an action with `--observe-ocr`): the operator gives it with `goldfinger setup` (see [diagnose.md](diagnose.md)): report it, and do not retry. The Safari reads (see [safari.md](safari.md)) need more, which the message names: `text --via apple-events` and `safari-tabs` the Automation grant for Safari (the operator runs `goldfinger setup --safari`, or turns it on in the Automation pane when refused), `text --via apple-events` also Safari's "Allow JavaScript from Apple Events" setting, and `--via extension` goldfinger's Safari extension turned on and allowed on the page's site. Each is the operator's: never change a Safari setting yourself. |
| `not_found` | The pid, window or bundle id (`launch`) is gone, or the window has no accessibility tree (another desktop, only with `--background` or out of the focus fallback's reach; for `window-frame`, no accessibility counterpart) or closed while `window-frame` moved it: list apps or windows again. A message ending `the screen is locked, …` (`observe`, `replay`): the Mac is locked, which only the operator can undo: tell them, and wait for the unlock (see [targets.md](targets.md)). A `replay` stopped there had already run its steps before `k`, and running the file again repeats them. A `replay` step or a replayed `hover --click` whose observe the walk's time cut, its message naming the cut: the app answered too slowly for a whole walk (see [sessions-and-replay.md](sessions-and-replay.md)). `record-stop` on a live session that is not recording. `replay`: a missing file, or a step's app, window or element not found, a replayed `hover`'s pressed element included. A `replay` step or a replayed `hover --click` whose element's role and title more than one element with an index has, its message naming the count and saying the descriptor is ambiguous, with nothing sent: record a target whose role and title are unique, or act on that step by hand (see [sessions-and-replay.md](sessions-and-replay.md)). `hover --click`: the observe in its hold found no window or tree, and nothing was clicked. `menu`: no menu bar, an item gone while the menus were walked, or a segment matching no item: fix the path from the titles the message lists. `find`: the window holds no web area, as a native one (Finder, a SwiftUI app) does, since AppKit offers no search, or its web engine offers no search: use `observe` (with `--max-nodes`), or act through the app's own UI. `open`, a file no app opens by default, an `--app` no installed app has, an item no app claims, or a file gone since the client's check (nothing opened); `hide`, `unhide`, a pid `apps` does not list; `window-state`, a window on another Space (with `--background`); `perform --custom`, a label no custom action has, or two share ("ambiguous"), nothing sent: read the labels in `custom_actions` again. `observe` of a window at the pop-up menu level that no `click --right` (or, `show-menu`) (or, `status-item`) reported, or whose menu neither lookup finds: open the menu with `click --right`. A hidden app's minimized window, or its window on another Space; `window-state restore` of a full-screen window the daemon did not make so, while its Space does not show (the message names the app's Exit Full Screen menu item); `text`, a window with no web area or an element with no text; `text --via apple-events` and `safari-tabs`, a Safari that quit or a window it has no id for; `--via extension`, a window the extension does not find (a private one) or a tab with no web page it may read (the Start Page); `setup --safari`, Safari does not run (the operator opens Safari and runs it again); a `batch` text reference whose text no entry of its step's read holds, or two do ("ambiguous"), nothing sent: act on the entry's own `target` instead. `set-value` on a native pop-up button whose menu has no item with that title, nothing picked, the message listing the titled items: use one of those titles. The verb closes the menu before it replies; when the message says the menu still showed or may still show, tell the user (see `set-value` in [actions.md](actions.md)). `status-item`, a pid no running app has, an app with no menu bar icons, no icon at `<index>` (list the icons again with `status-items`), or an icon or item gone while it was read; with `--item`, an icon that lists no menu, or a segment of the path that matches no item, nothing pressed: fix the path from the titles the message lists. `web-launch`, a bundle id no installed app has; `web-pages`, `web-dom` and `web-script`, a pid no live process has, or an app whose pipe has closed, as at its exit (`web-launch` it again), and for `web-dom` and `web-script`, a `--page` id no page has, or an app with no page: list the pages again with `web-pages` (see [web-apps.md](web-apps.md)). |
| `stale_snapshot` | Observe again, then act on the new snapshot. A web element its parent no longer holds counts as gone. A text target's text no longer shows at its point (a scroll, or the text changed), and nothing was sent; for `ocr` and `find-text`, the daemon no longer holds the snapshot. In a Chromium-family app, a pixel or text target whose page moved inside its window, as Chrome's debugger bar moves it, and nothing was sent: take a new `capture` or `observe --screenshot` and read the point off it, never the old target again (see [chrome.md](chrome.md)). A pixel or text target on a window its PNG showed over its window (a sheet or a popover) once that window closed, moved or resized: observe again. |
| `invalid_target` | Fix the target: a malformed id, an index past the snapshot, a pixel target without a screenshot or outside it, a text target past the snapshot's text, a pixel or text target for `set-value`, `reveal`, `perform` or, `text`, a window not Safari's for `text --via apple-events`, `--via extension`, `observe --via extension` or `safari-tabs`, an element target on a `capture`'s snapshot, an `ocr` or `find-text` of a snapshot with no screenshot or of a `capture`'s, a `step<k>:` target outside a `batch`, a `drag` whose `to` or a `via` is in another window than its `from`, or whose path needs more than 400 events, or a `hover --click` index past the observe taken in its hold. For the web verbs (see [web-apps.md](web-apps.md)): a `web-launch` of an app that is not Electron, a browser among them, or of one that runs, its message naming `goldfinger quit <pid>` (quit it, then `web-launch` it); a `web-pages`, `web-dom` or `web-script` of a process that this daemon's `web-launch` did not start, its message naming `goldfinger quit <pid>`, then `web-launch`; or a `web-dom` or `web-script` with no `--page` on an app with two or more pages, its message listing their ids (pass one as `--page`). |
| `background_unavailable` | Nothing was activated or sent. Each case below that the focus fallback lifts comes only with `--background` (see the focus fallback in [focus.md](focus.md)): keep the flag while the user must keep the screen as it is, else drop it. Also a focus fallback whose Mission Control shortcuts ("Move left a space" and "Move right a space") are off or set to keys other than Control-← and Control-→: the setting is the user's, so tell them. A `cmd` combo (a menu shortcut reaches only the active app): click the control, or press its menu-bar command with `menu`. `hide` of the frontmost app, which would move the user's focus (hide another app, or leave it); a `click` on a window's green title-bar button, which would enter full screen (frame the window with `window-frame`, or use `window-state <window_id> full-screen`); a `perform` of `raise` or `zoom-window`, or of any action on that button (a context menu opens with `click --right`). A verb that needs a hidden app's window on screen, its message naming `unhide <pid>` (see A hidden app's window in [find-windows.md](find-windows.md)): `unhide` the app, or use a verb that reaches it hidden. A mouse event this platform cannot aim into a background window: use an element target or another route; for a `drag` refused even with `--foreground`, no flag or target lifts it. A single left click into background web content outside Chromium, WebKit's or Firefox's (see [targets.md](targets.md)), a `hover --click` press's mouse fallback included: only when no element at the point offers a press (a `<canvas>`), the element is in another window or none, or the app rejected the press; target the element. Also a `keys` pixel target in such content (nothing sent), and a `type` pixel target there whose press left its element unfocused (the press was sent, no text). In LibreOffice, which places each mouse event at the mouse pointer (see `click`, LibreOffice, in [actions.md](actions.md)): a `click` with `--double`, `--right` at a pixel, a rejected press's mouse fallback, or a point whose element reads disabled; a pixel target of `click`, `type` or `keys` where no element takes a press or the focus; every `scroll`; and a `drag` whose `from` is there, even with `--foreground`: target an element, or reach the cell with `click` or `keys`. |
| `action_failed` | The app rejected the action or value: observe the state before another try. An element that needed mouse events has no visible part in its window, or none its app's hit test names it at (nothing sent; see [actions.md](actions.md)): `reveal` it (web content; see [targets.md](targets.md)), then act on it; a native element has no such action, so `scroll` its scroll view, observe again and act on the new snapshot. `reveal`: the element offers no scroll-to-visible action, as no native element does, or the app rejected it; nothing scrolled. `type`: a WebKit field given no text (a date or time field, an element that is not editable, a field holding text whose count did not move), or a native secure field that holds text, is not being edited, or whose caret did not reach the text's end; no keys were sent. `perform`: the element does not list the action (nothing sent; the message names what it offers), or the app answered an error, and the action may have run: observe first. `window-state`: the window cannot be minimized (nothing written), the app rejected the write, the state did not read back within 2 s, or, for `restore` and `full-screen`, the app did not come frontmost (nothing written); a `minimize` of a full-screen window (nothing written: `restore --foreground` takes it out first), or a `full-screen` of a window that cannot go full screen, as one that cannot be resized, a panel, a window with a sheet open or a minimized one (nothing activated). `open`: LaunchServices refused the open, its codes in the message. `hide`, `unhide`: the app's hidden state did not change within 1 s. `window-frame`: the window is minimized (nothing written: `window-state <window_id> restore --foreground` first), not movable or resizable (nothing written), a write was rejected (part may have landed), or no read-back matched: the platform held its position off the request (a title bar kept below the menu bar), or its frame kept changing, the message naming both frames: run `windows`. `clipboard-read`, `clipboard-write`: clipboard access is denied (nothing written), or the user refused the read at the paste alert while the clipboard held a type the read asked for: the operator allows the setting the message names: report it. A write refused after the clipboard was cleared left it empty, and says so. `clipboard-read --all`: the clipboard's image reads as neither a PNG nor a TIFF, and no file was written. `menu`, `drag`: the app did not come frontmost within 1 s (nothing sent; the app before was put back if the focus moved). `menu`: nothing pressed, as the path ends at an item that opens a menu, like a menu bar title (end it at a command inside), or at a disabled one (it needs a state the app is not in, say a selection: observe, change it, press again). Without `--background`, a press the app rejects, and an item disabled in the background of an app that is not frontmost, run again with the app activated (see the focus fallback in [focus.md](focus.md)), so a disabled one here is an item of the frontmost app, or one still disabled in front, whose message ends with the app activated and the app restored. `record-start`: the session is already recording (that recording goes on: `record-stop` first), its files or video would not start, or another session's recording has video. `hover`: refused before the pointer moved, as another window, or none, is at the point, the hit test went unanswered, or a button is held; or the platform would not move the pointer, the message saying where it was left (see Hover in [actions.md](actions.md)); or its `--click` press failed as `click`'s does. `glide`: the element has no visible part or position, and the cursor did not move. `text --via apple-events` and `safari-tabs`: Safari answered with no page text, or with another error, named with its number; for `safari-tabs`, the tabs changed between its reads: call again. `text --via extension`: Safari could not say whether the extension is on, or the extension gave another error. `setup --safari`: the grant's first read was `unknown`, so nothing was raised. `observe --ocr`, `ocr`, `find-text` and a text target's check (nothing sent): Vision failed, or a recognition abandoned at its 5 min ceiling still runs, which `goldfinger stop` clears: read `goldfinger status --json` first, run it, and name the sessions and apps it ended (see [diagnose.md](diagnose.md)); for `ocr` and `find-text`, also the snapshot's native capture could not be read. `observe --detect` (no snapshot, nothing partial): the build ships no detection model ("this build has no detection model", refused before the walk), Core ML failed, or a detection abandoned at its 120 s ceiling still runs, which `goldfinger stop` clears: read `goldfinger status --json` first, run it, and name the sessions and apps it ended (see [diagnose.md](diagnose.md)). `set-value` on a native pop-up button: a disabled button (nothing sent); a disabled item, a menu with no items within 1 s or a rejected item press (nothing picked); or a read-back that still differs after the press. The verb closes the menu before it replies; when the message says the menu still showed or may still show, tell the user (see `set-value` in [actions.md](actions.md)). `status-item`: with `--item`, a disabled item, or one that opens a submenu, which a press would only show (nothing pressed: end the path at a command inside it); or the app rejected a press, the message naming the `AXError`. For the web verbs (see [web-apps.md](web-apps.md)): `web-launch`, an app that exits, or closes its pipe, before it gives a page, its message naming the exit status or signal (an app that refuses every DevTools switch, as Claude's desktop app does: only `observe` reaches it), an app that cannot be started, or a CDP error; `web-pages` and `web-dom`, a CDP error, which the message names, or for `web-dom` a reply with no root node or no HTML; `web-script`, a script that throws or whose promise rejects, its message naming the line and the exception's text (read it as data, as the page wrote it), a result past 10 MiB of JSON, or a CDP error, as for a result CDP cannot return by value (a cycle): fix the script, and remember it may have acted before it threw. |
| `usage` | Malformed arguments (exit 2): fix the call; `goldfinger --help` lists the verbs. Over MCP, every `usage` a tool call returns ends with that tool's arguments in place of the CLI's help line, whichever check refused it (the schema's, the parser's, a CLI input reader's such as `open`'s item checks, or the daemon's): the required ones first, each marked `(required)`, as in `the find tool takes no argument "query"; the find tool takes: window_id (required), role, text, limit`, and a tool with none ends `; the policy tool takes no arguments`. Fix the call with those names, not the CLI's flags; `code`, `retryable` and the text before that end stay the CLI's. The CLI's own message keeps its help, and so does a `batch` entry's `error`. Also `--background` with `--foreground`, or on a command that takes no `--background` (see the focus fallback in [focus.md](focus.md)): drop one. Also a refused `batch` (a step's own bad args fail only that step, after the ones before it ran), a `replay` file that is not a trajectory its version replays (format 1 included: record it again), a command that requires `--session` run without it (see [sessions-and-replay.md](sessions-and-replay.md)), `find` with neither `--role` nor `--text` or a `--limit` outside 1–2,000, an `ocr` or `find-text` with a missing or malformed snapshot id or `--region`, a `find-text` whose text is empty once trimmed, a `clipboard-write` with no type or an empty one, an `--image` that is not a PNG or passes 32 MiB, a `--file` where nothing is (the message names it), a `capture` region outside the window (the message gives its size), a scale outside 0.25–4 or a PNG past 4,096 px, an `open` item the client's checks refuse (see [find-windows.md](find-windows.md); nothing sent), a `perform` with neither or both of an action and `--custom`, or of `press`, `pick`, `scroll-to-visible` or any name outside the six (the message names `click`, `reveal` or the six), `window-state minimize --foreground`, and `--ocr-language` without `--ocr` or with a code Vision does not read (the message names each), `--observe-ocr` without `--observe`, `--foreground` on a `perform` of any action but `show-menu` or with `--custom`, a `batch` step whose args carry `foreground`, a `batch` text reference to a step without both `observe` and `observe_ocr`, or with an empty text, and `text` with both or neither of a window id and a target, a target with `--via apple-events` or `--via extension`, or a `--limit` outside 1–100,000; a `--max-nodes` outside 1–20,000 (1–2,000 before), and `observe --a11y` with `--via extension`, a `web-script` whose `--file` does not open, is not UTF-8 or passes 10 MiB, or whose `--timeout` is outside 1–18,000, and a `web-dom` `--limit` outside 1–1,000,000; and, when `goldfinger --version` is below 0.20.0, a call written as this skill writes it: upgrade (see [diagnose.md](diagnose.md)). |
| `timeout` | Reads (`status`, `apps`, `windows`, `status-items`, `observe`, `screenshot`, `capture`, `clipboard-read`, `session-list`), `session-cursor`, `glide`, `reveal`, `hide` and `unhide` may be retried; a `clipboard-read --all` that passed its limit after writing its PNG leaves that file in `$TMPDIR` with no path in the reply. `observe --ocr` after a minute when it follows a first use (see [observe.md](observe.md)), or read a large window in parts with `--ocr-region`. `observe --detect` at once: a detection that passed its time (under 8 s and what is left of the verb's 20 s), one from an earlier request still running, or too little of the limit left; a slow first load runs on to finish, so the next call is warm. `find` may be retried too: a search past the 20 s limit keeps no snapshot. So may `text` and `safari-tabs`. The first read in each other `--ocr-language` compiles its model (about 14 s for `ar-SA`): observe again a minute later. So may `ocr` and `find-text`, and any action whose text target's check timed out, which sent nothing (see [targets.md](targets.md)). So may any verb that waited its whole 20 s limit behind other requests (the message says `<verb> waited 20 s behind other requests and did not run`, and `retryable` is true): it never ran, so nothing landed. So may a focus fallback whose keyboard and mouse were not still for 0.5 s within 3 s, or whose verb's limit left too little time for the fallback: it switched nothing and sent nothing (see the focus fallback in [focus.md](focus.md)). Retry once the user's keys and mouse go still. A verb that captures the screen (`observe --screenshot`, `--ocr` or `--detect`, `screenshot`, `capture`, a text target's check) is `timeout`, retryable, when ScreenCaptureKit gave no image within 5 s, or at once, naming it, when an earlier capture, or the Screen Recording check of `status` or `record-start --video`, still runs: retry. One in flight past a minute says that `goldfinger stop` clears it: read `goldfinger status --json` first, run it, and name the sessions and apps it ended (see [diagnose.md](diagnose.md)). So is an `observe` whose walk had under 0.5 s left or whose time cut the window's own reads, keeping no snapshot (see The walk's time in [observe.md](observe.md)). Anything else may have landed and is not retryable: observe before repeating an action, list apps before a `launch` (it may still open), list windows before an `open` again (it may still open the items), observe before a `perform` again, check a `window-frame` or a `window-state` with `windows`, a `clipboard-write` with `clipboard-read` and a `session-start` with `session-list`. A `batch` timeout has no entries: observe before repeating any step. A `menu` timeout says whether it came while the menus were walked (nothing pressed) or at the press; after the press, observe the app's windows first. A `click --right` or `perform … show-menu --foreground` whose app gave no answer within 5 s but opened one new menu is no `timeout`: it succeeds with `menu_window_id`, after about 6 s. A `set-value` on a native pop-up button that is `timeout` pressed no item, and the verb closed its menu before it replied, unless the message says the menu still showed or may still show (see `set-value` in [actions.md](actions.md)): observe before you set it again. A `status-item` that is `timeout` is not retryable: the app gave a read no answer within 5 s, before anything was pressed, or, with `--item`, gave the item's press none, and that press may have landed: check the app's state before you press again. For the web verbs (see [web-apps.md](web-apps.md)), `web-pages` and `web-dom` may be retried: the app gave no answer within the verb's limit, or CDP answered `Execution was terminated`. A `web-launch` timeout is not retryable: no page showed within 15 s, but the app runs with the pipe and may still load: call `web-pages <pid>` a moment later, or quit it as the message says. A `web-script` timeout is not retryable either: its script passed its `--timeout`, or its promise never settled, and it may have acted, its pending callbacks still running: read the page's state before you run a script again, and start a long one as a promise kept on `window`. |
| `daemon_unavailable` | Retry when `retryable` is true (a `reveal` stays retryable once sent, as repeating it sets the same state). When the message says the action may have landed, check it as for `timeout` first: a `batch` may have run steps, a `record-start` started a recording, and a `web-launch` started an app (read `status`'s `web_apps`) and a `web-script` ran its script. When it comes back on retry, run `goldfinger doctor --json` (see [diagnose.md](diagnose.md)). |
| `version_mismatch` | Two goldfinger versions met. Use the newer `goldfinger`. `goldfinger stop` and a retry also clears it, but stops the daemon other agents share. |
| `session_limit` | All six session colors are held, so `session-start` started nothing. End a session of yours, or wait for one to idle out, then retry. |
| `session_not_live` | The `--session` id is not live: never started, ended, idled out (its recording closed too) or an earlier daemon's. Nothing ran, and the same id fails again: run `goldfinger session-start`, and use the new id. |
| `denied` | The user's app policy refuses the verb on its app, and nothing was sent (see [policy.md](policy.md)). The message names the verb (for a `batch`, the step's position), the bundle id, its tier and where the tier came from (`policy.json` or the default list); for a broken file, it names the file and why it does not parse. No retry, relaunch, grant or `--foreground` lifts it, and only the user changes the file. Stop: do not retry, and do not reach the app another way. Tell the user the verb, the app and its tier, or the broken file. A refused `batch` ran no step, unless a step checked as it ran was refused after the steps before it ran; a `replay` ran the steps before. |
| `not_running` | A `voiceover` verb found no VoiceOver running, and nothing was sent; or VoiceOver quit before it answered, and a `do`, `type` or `press` may have landed. Run `goldfinger voiceover start <pid>`, then `goldfinger voiceover speech` to see where the cursor is, before you send the verb again. |

Trust `retryable`: it says whether repeating the same request is safe, never whether it worked.
